# Дашборд трафика сайта

Статический дашборд посещаемости: визиты по источникам переходов, помесячно,
поквартально и по годам. Данные лежат в Google Таблице, забираются через
прослойку на Cloudflare, отображаются без серверного рендеринга и без внешних
библиотек.

**Живая цепочка данных:** Google Таблица → Cloudflare Pages Function
(`/api/traffic`) → браузер.

## Что показывает

| Блок | Что отвечает |
|---|---|
| KPI-строка | визиты за период, динамика к прошлому периоду, доля поиска, средний месяц, пиковый месяц |
| Динамика визитов | стопка по источникам за каждый месяц, квартал или год |
| Структура источников | из чего складывается трафик за период — доли и абсолюты |
| Период к периоду | тот же отрезок против предыдущего такой же длины, по каждому источнику |
| Поисковые системы | Яндекс, Google и прочие внутри поискового трафика |
| Сезонность | тепловая карта год × месяц: где повторяющиеся пики и провалы |
| Таблица | все периоды с сортировкой и выгрузкой в CSV |

Фильтры (период, шаг, набор источников) пересчитывают **всё**, что ниже них,
включая KPI, графики и таблицу.

Дашборд подхватывает тему системы, имеет собственный переключатель светлая/тёмная
и раз в 5 минут тихо обновляет данные.

## Как считаются периоды

Единственный источник чисел — посуточный лист. Месяцы, кварталы и годы
собираются в браузере из дней, поэтому цифры в KPI, графиках и таблице не могут
разойтись между собой.

* **Неполные периоды отбрасываются.** Месяц считается за месяц, только если в
  данных есть его последний календарный день; квартал — если в нём три полных
  месяца; год — если двенадцать. Лист размечен на годы вперёд, и хвост текущего
  месяца иначе тянул бы вниз и динамику, и средние. Что именно отброшено,
  написано в подвале страницы.
* **Окно выравнивается по шагу.** «Последние 24 месяца» при шаге «год» — это два
  последних полных календарных года, а не 24 месяца, нарезанных как попало.
  Фактический отрезок всегда подписан под заголовком графика.
* **Сравнение — с предыдущим отрезком такой же длины**, идущим сразу перед
  выбранным. Если такого отрезка в данных нет, дельта показывает «—».

## Структура

```
public/
  index.html            разметка
  assets/styles.css     токены светлой и тёмной темы, компоненты
  assets/app.js         загрузка, агрегация по периодам, фильтры, рендер
  data/fallback.json    снапшот таблицы на случай недоступности прослойки
functions/
  api/traffic.js        Cloudflare Pages Function — прослойка к Google Sheets
scripts/
  snapshot.mjs          обновление снапшота (переиспользует код функции)
wrangler.toml           конфиг Pages: каталог сборки и переменные
```

## Как работает прослойка

`functions/api/traffic.js` отвечает на `GET /api/traffic`:

1. Параллельно ходит в `gviz/tq` Google Таблиц за двумя листами и приводит ответ
   к стабильной JSON-схеме (`{ ok, source, fetchedAt, columns, days[], engines[] }`).
2. Кэширует ответ на edge Cloudflare — Google отдаёт `no-store`, поэтому TTL
   держим сами (`CACHE_TTL`, по умолчанию 300 секунд).
3. Отдельно хранит **последний удачный ответ**. Если Google лёг, отдаётся он
   с заголовком `x-cache: STALE` — дашборд не белеет, а честно пишет об этом.
4. Не пускает ID таблицы в браузер: фронтенд знает только про `/api/traffic`.

Строки отдаются массивами, а не объектами: дней больше трёх с половиной тысяч,
и на объектах ответ распухает втрое без единого лишнего байта смысла.

Полезные заголовки ответа: `x-cache` (`HIT` / `MISS` / `BYPASS` / `STALE`) и
`x-data-source`. Принудительно обновить: `GET /api/traffic?refresh=1` — это же
делает кнопка «Обновить».

Если прослойка недоступна (например, открыли `public/` как статику), дашборд
загружает `data/fallback.json` и показывает баннер о том, что данные снапшотные.

## Требования к Google Таблице

* Доступ: «Любой, у кого есть ссылка — читатель». Ничего публиковать в веб
  отдельно не нужно, `gviz` работает по этому же доступу.
* Нужны два листа, имена задаются переменными окружения:

**`По дням`** (`SHEET_DAILY`) — первая колонка с датой, дальше пять колонок с
визитами. Колонки ищутся по корню слова в заголовке, нумерация вида
«1. Переходы из поисковых систем» не мешает:

| Поле JSON | Как ищется в заголовке | Запасная колонка |
|---|---|---|
| `date` | первая колонка листа | A |
| `search` | `поисков` | B |
| `direct` | `прям` | C |
| `ads` | `реклам` | D |
| `links` | `ссылк` | E |
| `internal` | `внутренн` | F |

**`Поисковые системы (для графика)`** (`SHEET_ENGINES`) — дата начала месяца и
разбивка поиска:

| Поле JSON | Как ищется в заголовке | Запасная колонка |
|---|---|---|
| `month` | первая колонка листа | A |
| `yandex` | `яндекс` / `yandex` | C |
| `google` | `google` / `гугл` | D |
| `other` | `проч` / `остальн` | E |

Строки с датой, но без чисел пропускаются — лист размечен на годы вперёд, и
пустые будущие даты не должны попадать в данные.

## Деплой на Cloudflare Pages

Пошаговая инструкция со всеми настройками, подключением поддомена, закрытием
доступа и диагностикой — в **[DEPLOY.md](DEPLOY.md)**. Коротко:

1. Cloudflare Dashboard → **Workers & Pages** → **Create** → **Pages** →
   **Connect to Git**, выбрать этот репозиторий.
2. Настройки сборки:
   * Framework preset — **None**
   * Build command — оставить пустым
   * Build output directory — **`public`**
3. Deploy. Каталог `functions/` Cloudflare подхватывает сам — `/api/traffic`
   появится без дополнительной настройки.

Переменные `SHEET_ID`, `SHEET_DAILY`, `SHEET_ENGINES` и `CACHE_TTL` заданы в
`wrangler.toml`. Для Pages этот файл — источник истины: в дашборде переменные
видно, но редактировать их нельзя. Чтобы управлять ими из интерфейса, удалите
блок `[vars]` и задайте значения в **Settings → Variables and Secrets** отдельно
для Production и Preview.

Разовый деплой из командной строки:

```bash
npm install
npx wrangler pages deploy public
```

Домен подключается в **Custom domains** проекта. Дашборд внутренний — закройте
его **Cloudflare Access**; в разметке уже стоит `noindex, nofollow`.

## Локальная разработка

```bash
npm install
npm run dev          # wrangler pages dev public → http://localhost:8788
```

`wrangler pages dev` поднимает и статику, и функцию, поэтому `/api/traffic`
работает локально ровно так же, как в проде.

Без wrangler можно открыть просто статику (`npx serve public`) — дашборд
переключится на снапшот и покажет об этом баннер.

Обновить снапшот:

```bash
npm run snapshot
```

## Настройка под себя

* **Источники и их цвета** — `SOURCES` в `public/assets/app.js`. Слот цвета
  закреплён за источником навсегда: выключение соседа не перекрашивает
  остальные.
* **Пресеты периода** — список `<option>` у `#f-window` в `public/index.html`,
  значение — длина окна в месяцах (`0` — весь период).
* **Пороги тепловой карты** — `heatBins`. Они берутся по квантилям, а не равными
  шагами: распределение визитов длиннохвостое, и на равных шагах вся карта
  схлопнулась бы в один оттенок.
* **Частота автообновления** — `CONFIG.autoRefreshMs`.
* **Палитра** — CSS-переменные в начале `public/assets/styles.css`. Пять
  категориальных цветов проверены на различимость при дальтонизме в обеих темах;
  тепловая карта использует одну голубую шкалу (на тёмной теме она развёрнута,
  чтобы «больше» оставалось заметнее фона).
